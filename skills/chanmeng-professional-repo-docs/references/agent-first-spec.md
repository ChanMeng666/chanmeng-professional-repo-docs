# Agent-first documentation spec

These repos are meant to be **operated by AI agents** (Claude Code, GitHub Copilot, Cursor, Codex).
Three pieces make a repo agent-first.

## 1. The README agent notice (top of every README)

Placed above the hero, verbatim:

```markdown
> [!IMPORTANT]
> ### 🤖 Read this with your AI agent — don't read it by hand.
> This repo is written agent-first. Point Claude Code, GitHub Copilot, Cursor, or any agent at it:
> *"Read the README and AGENTS.md, then help me run / extend this."*
> Structure + AGENTS.md are optimized for agent comprehension.
```

The point: a human visitor shouldn't slog through the README — they should hand it to their agent,
which can read the README + `AGENTS.md` and immediately run or extend the project.

## 2. AGENTS.md (the agent-facing project guide)

`AGENTS.md` is where an agent learns how to *work in* the repo (vs. the README, which says what the
project *is*). A good `AGENTS.md` has:

- **Project overview** — one tight paragraph: what it is, the stack, the default branch, the repo URL.
- **Commands** — the real dev/build/test/run commands (the scaffold pre-fills these from the detected
  stack). Keep them accurate; an agent will trust and run them.
- **Architecture & conventions** — where the entry points are, the directory map, key abstractions,
  and any patterns that diverge from framework defaults. Save the agent from reverse-engineering.
- **Gotchas & anti-patterns** — the silent traps ("don't edit generated files in `dist/`", "this
  framework version differs from your training data — read the local docs"). This section earns its
  keep; it's the stuff that wastes an agent's time.
- **Reading order** — README → AGENTS.md → CONTRIBUTING.

Chan Meng's existing exemplars: `leviathan/AGENTS.md`, `eatropolis-website/AGENTS.md`,
`sunostats/AGENTS.md`. When the framework has breaking changes vs. model training data, add a short
`<!-- BEGIN:nextjs-agent-rules -->`-style banner at the top pointing the agent at the local docs.

**Fill the stubs.** The scaffold leaves architecture/gotchas as prompts — complete them with what you
know about the project. An empty AGENTS.md helps no one.

## 3. llms.txt (optional machine-readable map)

Follows the [llms.txt](https://llmstxt.org/) convention: a terse map (about + key documents + a
"for agents" note) that points an LLM at the README, AGENTS.md, CONTRIBUTING, CHANGELOG. Generated by
default; skip with `--no-llms` for tiny projects.
